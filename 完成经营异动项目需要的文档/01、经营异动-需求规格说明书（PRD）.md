## 0. 阅读约定与文档权威

本文把业务问题、需求、口径与验收放在一起；TDD 解释实现机制；开发步骤负责把需求映射到代码、验证证据和面试表达。三份材料共同覆盖：

> 业务问题 → 需求拆解 → 技术选型 → 架构设计 → 代码实现 → 数据流转 → 异常排查 → 性能优化 → 业务价值 → 面试表达。

这是对现有项目资料的整编，不是新增范围的批准，也不凭本文把历史失败改成通过。现有已确认的[需求冻结基线](../docs/阶段1_需求分析与MVP设计_V2.md)仍负责业务授权与范围；[原总体方案](../docs/总体技术设计与开发实施方案.md)保存技术确认背景。发现冲突时登记差异，不在代码或 Prompt 中静默改变分母、权限或验收门槛。

本文使用四种证据状态：**目标要求、源码可定位、历史运行有记录、本次重新验证**。有代码不能推出可运行；历史专项通过不能推出当前完整通过；付费模型返回成功不能推出业务判断正确。2026-10-16 本次工作仅整编文档，没有重新执行模型、全量验收或真实业务验证。

## 1. 业务问题与产品价值

### 1.1 谁在什么场景下遇到什么困难

运营发现某商品销量下降、退款增加或评分变化后，通常要切换销售报表、库存、退款明细、评论、客服与运营记录。数据窗口和粒度不同，很容易把“本周退款”除以“本周销量”，把库存总数当可售库存，把几条差评当全部订单的解释。调查结果散落在表格和聊天中，修改后没有可比复查，也可能多人重复调查。

系统服务于商品负责人、运营、品控、客服和数据管理员。它应让用户回答五个问题：发生了什么？数据可靠吗？已查明什么、还有什么没查？谁接下来做什么？什么时候检查是否改善？

### 1.2 价值主张与可验证结果

| 痛点 | 产品能力 | 预期价值 | 证明方法 |
| --- | --- | --- | --- |
| 跨表人工对齐 | 统一对象、窗口、来源与指标 | 减少搬运和重复计算 | 同类事件前后调查主动用时 |
| 相似告警重复出现 | 持续事件、恶化判断与通知去重 | 减少重复打扰 | 重复通知率、事件合并准确性 |
| 结论无法回查 | 数字、原文、版本与引用链 | 降低核查成本 | 引用回查及错对象测试 |
| AI 直接猜原因 | 规则事实、调查线索、反证和缺口 | 提高解释可信度 | 独立人工判定支持关系 |
| 有报告无处理 | 指派、动作、观察与到期复查 | 推动问题处理 | 可执行报告比例、到期完成率 |

产品不承诺证明因果、提高销量或降低退款。没有对照与真实业务验证时，不能将指标回升归功于系统。

### 1.3 与现有工具的关系

Seller Central、ERP 和 Excel 是事实来源与原工作流。系统增加跨来源核查、证据追溯、持续跟进和受控调查能力；验收应与运营实际流程比较。不能仅以“接入大模型”“搭建多智能体”“自动生成长报告”作为价值证明。

## 2. 范围与约束

### 2.1 完整产品范围与当前交付

商品与负责人映射、数据导入与质量、指标和异常检测、事件队列、场景取证、反馈语义与检索、报告、内部处理复查、自然语言查询、有界自主调查、通知导出、权限和运维，属于完整产品目标。当前授权交付为内部演示、功能可用，智能质量仍须修复并实际验证；正式上线另按下表签收。

工程可以分工作包实施；智能质量门槛不因演示而降低，尚未通过的质量不得写成已完成。某店铺暂缺数据，仍须实现相应接入与缺失处理路径。

### 2.2 不包含的能力

广告优化及广告归因、竞品爬取、利润核算、赔偿索赔、跨商品全局因果分析、外部平台自动改价/补货/删除评论/联系买家，以及本次的外部 API 自动同步实现。公开网页不能替代店铺经营事实；默认不为调查开放全网搜索。

### 2.3 数据与运行约束

- 数据必须有使用权限；默认不导入买家姓名、邮箱和地址。
- 金额保留币种和税费范围；缺汇率不合成跨币种金额。
- 站点本地日历定义业务窗口，时间戳保留时区；默认排除进行中的当天。
- 单机部署需要停机恢复方案，不宣称高可用；个人电脑关闭不影响云端任务。
- 模型不可用时，指标、事件、已建证据、规则报告与人工处理仍可用。

范围依据为[2026-10-13 用户确认](../docs/内部演示范围与公开数据验证方案_2026-10-13.md)，优先于本整编稿的阶段措辞；冻结业务口径与质量门槛继续有效。

| 项目 | 当前内部演示完成标准 | 最终正式上线完成标准 |
| --- | --- | --- |
| FR-01—13、AC-01—26 | 在明确的公开评论/合成经营数据范围逐项验证功能、公式、授权、恢复和回查；缺证逐项列出，不据文件存在宣告通过 | 同样能力在授权真实报表、目标环境和真实业务范围签收 |

## 3. 角色与授权

| 角色 | 主要职责 | 必须检查的边界 |
| --- | --- | --- |
| 运营/商品负责人 | 查看事件、调查、分派、记录动作和关闭 | 角色能力与店铺/对象范围同时满足 |
| 品控 | 核查体验与安全线索、登记抽检结果 | 仅获授权对象；不因安全紧急而扩权 |
| 客服 | 查授权反馈、补充工单核查 | 不默认获得全部财务或原始订单权限 |
| 数据管理员 | 来源、字段映射、导入、质量与配置 | 不能绕过业务命令直接改历史结论 |
| 工作空间管理员 | 成员、授权、部署与审计 | 管理职责不能代替明确业务执行权限 |
| 定时任务/Agent | 以绑定身份执行限定任务 | 执行前重查授权，文本内容不能授予权限 |

页面隐藏按钮只改善交互；列表、详情、聚合、候选发现、证据、导出和后台任务均由服务端授权。只有会话 ID 或 UUID 不构成访问权限。

## 4. 贯穿案例：销量下降且退款增加

以下数字均为**教学用合成示例**，用于说明口径，不是项目成效或真实店铺数据。

对象为同一店铺 US 站的一个子 ASIN，销售/流量来源原生粒度为子 ASIN。数据共同完整截至 2026-10-07：

| 指标 | 基线：09-03 至 09-30（28 日） | 当前：10-01 至 10-07（7 日） | 正确解释 |
| --- | --- | --- | --- |
| 订购件数 | 560 | 70 | 日均 20 → 10，下降 50%；基线预期 140，少 70 件 |
| Sessions | 2,800 | 700 | 日均均为 100，没有流量下降证据 |
| 件数/会话转化指标 | 560/2,800=20% | 70/700=10% | 下降 10 个百分点，相对下降 50% |
| 退款交易数 | 14 | 14 | 日均 0.5 → 2；发生量增量为 10.5 笔（相对基线预期） |

退款交易可能对应前期订单；禁止用 14/70 宣称“本周产品退款率 20%”。若另有成熟发货队列：前一队列 8/200 个订单、后一队列 20/200 个订单在发货后 30 日内有效退款，则队列退款订单率为 4% → 10%。需同时显示观察期、订单去重和置信区间；缺完整追踪则不能计算。

完整业务闭环：

1. 数据管理员上传销售、退款、库存、反馈和事件表，先核查窗口与字段。
2. 确定性计算发现销量和转化指标下降、退款发生量增加，按问题族建立关联事件。
3. 先查可售、购物车、库存、价格促销，再核查子体结构、订单队列和反馈。
4. 假设发现包装负向原文，只能列为包装核查线索；没有订单/批次关联不能确认批次缺陷，也不能据此解释全部销量损失。
5. 保存证据和待核查任务；经授权由负责人安排尺寸/包装抽检，登记结果与变更生效时间。
6. 生效后满 7 个完整日检查经营指标；涉及退款队列时等待成熟及数据完整。分别报告动作完成、指标变化和因果尚未证实。

本节 560/70 等数值不对应现有回放夹具。可执行案例使用开发手册 8.1 的固定 2026-09-05 回放，基线 560、当前 28；不得将两组案例混作一次实测。

## 5. 交互方式与工作流

### 5.1 三类任务

| 层级 | 例子 | 行为 |
| --- | --- | --- |
| L0 查询 | “上周订单数是多少？” | 受限解析与领域查询，可直接回答，不必启动调查或生成文件 |
| L1 标准检查 | 每日扫描、导入后核查 | 确定性场景流程，生成事实、异常和规则候选 |
| L2 有界自主调查 | “这个商品最近为什么退款增多？” | 继承明确范围，依据新证据选择白名单工具、核查反证，按预算停止 |

L2 采用一个有界 Agent，不要求动态多 Agent。区分条件分支、规则 planner 和真实模型决策；中间证据改变后实际工具或参数改变，只能证明证据敏感性；选择是否正确、是否比固定流程有价值，另按 TDD 7.6 对照评测。

### 5.2 自然语言定位

明确问句、事件、页面上下文可供定位，采用对象和窗口必须可见。唯一合理对象自动继续；多个合理候选只在授权范围列出并澄清。显式输入与页面冲突需确认切换。“最近”优先沿用可见窗口，否则采用指标默认窗口和共同完整截止日。未定对象时只做定位查询，不业务写入。

### 5.3 调查顺序

| 场景 | 必查顺序 | 禁止推论 |
| --- | --- | --- |
| 销量下降 | 完整性 → 可售/购物车 → 可售库存 → 流量 → 转化 → 价格促销/运营事件 → 体验反馈 | 缺流量就把差评认定为销量下降主因 |
| 转化下降 | 分子分母 → 子体结构 → 购物车/库存 → 价格促销 → 页面和体验 | 以销量下降本身证明转化下降 |
| 退款退货增加 | 发生/队列口径 → 原因与子体 → 履约/工单 → 可关联批次/变更 | 将退款金额当缺陷件数、收到退货当退款 |
| 评分/反馈变化 | 页面快照/采集完整性 → 变体归属 → 主题极性与覆盖 → 其他来源 | 从评论均分推算页面星级 |
| 严重安全反馈 | 回查实际/否定/假设语境 → 对象 → 即时人工核查 | 低样本忽略安全，或自动宣告缺陷成立 |

工具无数据时，若其他有效方向存在则继续；剩余路径被关键缺口阻断才停止并形成补数建议。

## 7. 数据契约与指标字典

### 7.1 身份、粒度和版本

业务对象键为 `shop_id + marketplace_id + child_asin + seller_sku + fulfillment_channel`，内部 `product_id` 是代理键。保留 `native_grain` 和 `reporting_scope`：ASIN 级 Sessions 不复制到多个 SKU 后再相加；来源缺 SKU 时仅在原生层分析。父子调整前后不能无说明拼接。

每次导入保存来源、文件 SHA-256、报表类型/窗口/粒度、生成和导入时间、数据截至时间、完整性声明、契约/映射版本、原始行号。纠正历史需新事实版本或撤回记录，不能覆盖掉旧报告的依据。评论只默认关联商品；订单与批次关联必须有可靠事实映射。

### 7.2 来源最低要求

| 数据域 | 必要信息 | 不满足时 |
| --- | --- | --- |
| 销售流量 | 日期、来源粒度、订购件数；订单数/Sessions/购物车若提供 | 无 Sessions 不算转化；无订单数不把件数叫订单 |
| 订单发货 | 订单/订单行、商品、首次发货时间、件数 | 无明细不算成熟队列率 |
| 退款 | 交易 ID、订单关联、事件时间、金额/币种、冲正 | 只报可得发生量，不能金额反推件数 |
| 退货 | 记录 ID、关联订单、件数、事件语义、原因、处置 | 申请、收到、退款分列 |
| 库存可售 | 状态日期、可售/预留/在途/不可售及来源范围 | 总库存不能代替可售库存 |
| 反馈 | 原文、发生/评论时间、采集时间、评分、语言、变体 | 采集范围未知不宣称总体趋势 |
| 页面星级 | 展示对象、快照时间、星级 | 不能用采集评论均分补齐 |
| 价格促销/运营事件 | 对象、生效起止、币种、变更和依据 | 缺到手价/批次不虚构解释 |

数据由有权获取的业务导出提供，不假设平台接口提供完整评论或全部客服数据。

### 7.3 数据质量状态

统一 `ready / partial / stale / missing / invalid`。零只在完整报表明确为零，或契约允许缺行表示零时成立；其他缺行是未知。日源默认落后站点日期超过 2 日为过期，可按来源延迟配置。

比较截止日 D 取本次指标依赖日源共同最新完整日。不要为单独文本检索强行引入无关来源依赖；严重安全记录按最新导入即时核查，不等待日窗口。部分数据可显示事实，但不能参加要求完整分母的计算。

### 7.4 指标定义

| 指标 | 公式/语义 | 边界 |
| --- | --- | --- |
| 订单数 | 来源定义的对象内去重订单 | 与订单行数、订购件数分列 |
| 订购/发货件数 | 分别合计 units_ordered / shipped_units | 不混计销售阶段 |
| 销售额 | 来源定义下金额合计 | 标注币种、税费折扣范围，不称利润 |
| Sessions | 原生对象与日期的会话数 | 不按 SKU 销量摊分 |
| 件数/会话转化指标 | Σunits_ordered / Σsessions ×100% | 不是购买用户概率，可大于 100%；分母零返回不可计算 |
| 购物车占比 | 保留原始定义；有匹配权重才加权 | 无权重只显示日值或日均描述 |
| 退款发生 | 按退款交易日期统计有效交易/金额 | 冲正可追溯；不除以当期销售作队列率 |
| 退货发生 | 按固定的申请或收到日期统计 | 不能跨事件语义拼接 |
| 30 天队列退款订单率 | 首次发货分组中，30 日内有有效退款的去重订单 / 该组已发货订单 | 对象内去重；部分退款计一次；成熟且追踪完整才能比较 |
| 30 天队列退货订单率 | 同组在 30 日内发生固定退货事件的订单 / 该组已发货订单 | 名称说明申请还是收到；成熟边界按契约统一 |
| 退款/退货原因结构 | 同一事件/单位下原因计数或件数 / 全部同类计数或件数 | 显示未知原因；多标签不假定合计 100% |
| 页面星级 | 来源页面快照值 | 不由导入评论算术均分替代 |
| 采集评论均分 | 有效导入评论评分算术均分 | 仅解释已采集样本 |
| 主题负向占比 | 该主题负向及混合评论数 / 同窗口全部已分析评论数 | 多主题可重叠；分母固定，不用检索 Top K |

队列按首次发货的站点日期分组。有首次发货时间戳时，以实际时刻 T 计算 `[T,T+30天)` 并保留时区；仅有日期时，按冻结 PRD 的精度约定使用站点当天 00:00，结果必须标“仅日期、午夜近似”，不能称精确发货时刻。`metrics/cohort.py:event_time` 先用时间戳，缺失才回退日期；`cohort_from_facts` 的 limitations 明示该限制。观察覆盖完整且结束后才成熟；夏令时下时刻长度与日历日不同。保留这两种来源精度，不静默取消日期来源的既有业务授权。

### 7.5 反馈预测与经历去重

语义标签属于模型预测，保存模型、Prompt、taxonomy、schema、输入哈希和原文跨度。预测标签不作人工真值。标注覆盖分母为该窗口有效导入反馈，不能据其覆盖率推断覆盖全部买家。

评论默认 28 日对前 28 日；低样本双方等长扩为 56 日。各窗至少 30 条已分析评论、标注覆盖各至少 90% 才进入主题趋势判断，否则只描述样本。跨工单、退款、评论仅在可靠订单关系存在时合并为同经历；相似文字不能证明同买家。

## 8. 异常、统计与事件规则

### 8.1 窗口与可比性

经营默认当前 7 个完整日，对此前 28 个完整日，数量比较先化日均；成熟队列默认最近 28 个成熟发货日对前 28 日。新品历史不足则标基线不足，绝对可售状态与安全核查仍执行。促销、对象变化、来源切换和采集变化均提示可比性限制。

二项占比使用 95% Wilson 区间；独立两窗差值用 Newcombe 方法。只有差值区间不跨 0，才可称样本内统计差异。多主题显著性另做双侧 Fisher 检验并在同对象同扫描的全部被检主题上 BH 校正，q≤0.05；不得只校正挑出的显著主题。件数/会话指标、金额和页面星级不机械套用二项区间。统计差异不证明因果。

### 8.2 默认检测配置

下列数值继承既有产品默认值，属于可版本化设计参数，不是平台标准或实测最优值。

| 信号 | 默认条件 |
| --- | --- |
| 销量变化 | 日均相对变化≥30%，当前件数与基线预期差≥10，基线 28 日≥40 件 |
| 流量下降 | 日均 Sessions 下降≥30%，基线≥200 Sessions |
| 转化下降 | 两窗各≥100 Sessions，相对下降≥20%，绝对下降≥2 个百分点 |
| 队列退货/退款 | 两窗各≥100 个成熟订单，当前相关订单≥5，升幅≥2 个百分点且差值区间下界>0 |
| 当期退款退货突增 | 日均增加≥50%，当前 7 日比基线预期增量≥5；零基线时当前≥5 |
| 页面星级 | 同展示对象下降≥0.2 星，对照快照不超过 7 日 |
| 主题负向变化 | 满足覆盖/样本条件，当前主题负向及混合≥5 条，占比增加≥10 个百分点 |
| 可售/库存/购物车 | 新不可售或可售库存正转零；购物车连续两个完整日<80%且比基线日均下降≥20 个百分点 |
| 安全 | 任一新记录涉及实际起火、冒烟、伤害等疑似经历，立即人工核查，保留否定/假设语境 |

首次满足就建事件；“持续”要求连续两次含新增完整日数据的扫描。重复扫描相同数据不能增加持续性证据。

### 8.3 合并、排序与提醒

扫描记录由对象、指标、窗口、规则和数据版本标识；开放事件按对象与问题族合并。销售/转化、退款/体验、可售/库存、安全分别建族并可互相关联，时间接近不自动同因。父体汇总保留子体差异。

紧急度：安全/已确认不可售或断货 → 高风险销量或成熟队列 → 一般可行动信号 → 低样本观察。同级按超阈值比例、已知影响规模、持续天数、首次发现时间稳定排序。未知影响不捏造金额，安全不因未知规模降级。

通知限新事件、恶化、重开、任务分派和复查到期；同事件/类型/数据版本去重。恶化为等级升高，或偏离幅度比上次通知再增≥25%且仍触发原规则。新安全线索始终提醒。

## 9. 报告、处理与复查闭环

### 9.1 报告最小内容

首屏显示对象、异常、影响单位、数据截至时间、限制和下一步。详情必须能展开：当前/基线窗口、分子分母、子体分布、计算版本、已核查维度、支持/反向/冲突证据、缺失来源、候选排序依据和原始记录。

候选可空、并列或冲突；区分“已核实事件”“有支持的调查方向”“待验证线索”。不输出未经校准的原因概率。未命中不是反证，“外观满意”不能反驳“断电”。报告不以长度验收；模型不可用也可展示已验证事实。

### 9.2 事件与动作状态

事件：待核查 → 处理中 → 待观察 → 已关闭；待补数据为附加标记，暂缓记录到期时间。关闭需要责任人、理由和依据，可选已解决/误报/已知变化/重复。安全不得自动暂缓或关闭。30 日内同对象同问题族复发重开，超过 30 日新建并链接历史。

动作保存对象、待验证问题、负责人、期限、依据、生效日、完成记录、观察指标和复查日。调查草稿可暂缺负责人/期限；正式分派必须补齐和授权。完成任务不能直接把事件当已解决。

经营复查在生效后满 7 个完整日进行；队列复查需观察期到期与数据完整。样本不足延长并记录原因。新报告保存版本，旧证据和动作保留；显示动作完成、指标改善、因果未证实三个独立结果。

### 9.3 Agent 写入边界

可自动保存调查产物、证据关联和未指派核查草稿。正式内部任务自动执行需明确预授权策略，绑定能力、对象、负责人、期限和有效期。其他变更生成提案，由有权限的人批准精确版本；参数改变后旧批准失效。模型不能直写数据库或自行调用外部业务操作。

写入采用唯一命令和回执；崩溃/取消后展示已真实提交的记录，未执行提案不能冒称完成。

### 9.4 调查预算与停止

需求验证初值为 8 次模型决策、12 次只读工具调用、300 秒主动运行时间；步骤检查点数与模型/工具计数分别统计。token、金额和并发上限由部署配置确定，缺有效上限时禁用付费调用。当前 API 的 max_steps 并不等于上述三种预算均已落实，差异见 TDD。

预算耗尽、连续两轮无新增有效证据、重复同快照同参数、必要缺口阻断、取消或撤权时停止。显示完成/部分完成/待澄清/待补数据/取消/失败及具体原因。恢复不重置预算，不用拆子任务绕过总额；模型未知收费回执不能自动重发。

## 10. 页面与非功能需求

五类主要页面：事件队列、调查报告、处理复查、商品映射、数据源管理。自然语言入口内嵌工作流，不要求运营靠聊天完成所有操作。任务页展示简短步骤、工具与证据、停止原因和实际结果，不展示模型私有思维链。

| 编号 | 要求与验收条件 |
| --- | --- |
| NFR-01 正确性 | 同输入、规则、映射和标签版本可复现指标及标准排序；模型文本和探索路径不承诺逐字一致 |
| NFR-02 性能 | 8 核/16GB/SSD、最多 1,000 子 ASIN、180 日日数据、至少 10 万反馈/交易，验证 10 人并发；缓存队列/报告 P95≤3s，已有标签全量扫描≤15min |
| NFR-03 长任务 | 接口不等待全量导入/标注/调查，提供进度、错误与恢复；具体受理延迟独立测量，不以“异步”代替性能数据 |
| NFR-04 模型降级 | 默认单次 30s 超时、最多一次明确可重试失败；不确定收费/已派发无回执不自动重试；规则事实仍可用 |
| NFR-05 可靠性 | 扫描互斥、任务可恢复、重复投递无重复业务副作用，备份须实际恢复验证 |

| NFR-08 可观测 | 任务/调查/工具/模型/批次可关联，记录来源、版本、耗时、错误和脱敏日志 |
| NFR-09 安全 | 授权目录、服务端校验、上传限额、CSRF/会话管理、密钥不入库，外部文本只作不可信证据 |

## 12. 智能质量与业务验收

### 12.1 分层质量门槛

- 确定性数值、幂等、权限、状态与追溯用例全部通过，误差仅允许明确的展示舍入。
- 冻结中英文测试集：受限意图准确率≥95%，主题极性 Macro-F1≥0.85，检索 Recall@10≥0.85，引用有效率 100%。检索的当前评分契约见 TDD 7.6：冻结评测语料内按 development/validation/test 分别计算 micro Recall，各组均须达标；query macro 仅作补充诊断，不能替换门禁或外推全库召回。分别报告样本量、分层表现和漏检，不能一个总分掩盖安全/引用问题。
- 检索按实际相关原文片段/记录标注，不能只按文件名命中；存在多个有效来源时允许多真值。另测无答案、错对象、错窗口、否定、冲突与跨权限。
- 证据约束集禁止编数、错引用、越权、把缺失当反证或无依据因果。固定集零违规不宣称所有开放输入零风险。
- 严重安全规定正例全部进入人工核查，并单报否定/假设误报；模型裁判不能独立证明业务正确。
- 按商品/时间与重复连通组隔离开发和 holdout；开发集调参后不能继续把它叫独立测试。银标签只用于开发，独立人审才用于相应质量结论。

### 12.2 正式上线的真实业务验证（后续阶段）

完整产品影子运行≥3 周，≥2 名实际运营、≥10 个真实子 ASIN、≥30 个已核查事件；不足则延长或补真实历史回放，二者分列。合成数据证明机制，不证明业务收益；公开评论证明有限语义适用性，不证明真实店铺退款归因。

业务目标：单事件调查主动用时中位数比原流程降低≥30%（含数据准备分摊）；≥60% 报告产生明确核查/处理动作；一般已核查事件无效告警≤20%。安全与数据源告警独立分母。另报漏检、重复打扰、待补数据和到期动作完成率。

记录异常真假、解释有无证据、动作是否可执行三个独立维度；不同意原因排序不自动算误报。收益金额需要实际业务账与归因证据，不能由少售件数直接推算。

### 12.3 当前证据边界

截至本次查阅，仓库包含相关主线实现及大量专项测试。最近[智能质量执行记录](../docs/智能质量当前执行入口.md)与[累计实录](../docs/智能质量累计30美元循环实录_2026-10-14.md)仍明确：真实整轮质量和独立裁决尚未确认达标，存在未通过/未执行轨道。不同版本部分完成结果不能拼成一次整轮通过。本文不据历史原型 README 宣称生产可用。

正式上线发布需功能、口径、权限、可靠性、性能和真实业务门槛均满足，无未解决严重问题。只完成技术验收时明确标记业务验证未完成。

当前内部演示完成标准见 2.4；生产门禁未完成不阻塞内部演示，但质量缺证仍须如实展示。逐项实现与证据见开发手册第 13 节。

## 13. 变更与面试表达边界

变更指标分母、窗口、数据粒度、范围、执行权限或验收门槛必须登记：原因、影响 FR/AC、兼容/回补、验证与确认人。模型/Prompt/taxonomy/索引变更需新配置版本及相应回归。

可用于项目介绍的事实表述：
