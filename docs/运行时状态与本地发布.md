# 运行时状态与本地发布说明

> 本文合并自原 `stage6b_architecture.md`、`stage6b_core_mvp_release.md`、`stage6b_local_mode.md`、`stage6b_local_release_runbook.md`、`stage6b_bad_cases.md`、`stage6b_retrieval_eval.md` 六份文档。
> 描述**当前代码实际行为**，与需求文档 [阶段1 · 需求分析与 MVP 设计 V2](阶段1_需求分析与MVP设计_V2.md) 描述的目标架构是两回事，不要混读。

## 1. 当前可发布范围

本地可发布的核心由 Claim Store、ReviewSignal、Keyword 检索、Review Detail、Evidence Guard、SQLite 状态与 SSE 组成。

- **Keyword 是默认检索后端。**
- Qdrant 已冒烟测试，但仍为**实验性**；char-bigram Hybrid 为实验性回退。
- 发布路径分两条泳道：Core MVP（Keyword + Claim Store + ReviewSignal + Detail + Evidence Guard）与 Vector Retrieval（Qdrant）。**Core 泳道不得被实验性向量后端阻塞。**

当 `DEEPSEEK_API_KEY` 缺失时，`/api/v1/health` 报告 `execution_mode=deterministic_local`、`planner_status=deferred_external_model`。该模式仅支持本地开发与回归，**不能替代真实 Planner 或真实模型黑盒验收**。

已尝试的业务 Enrichment 产出了一个有效的 Yootech pilot 和部分 AILKIN 数据；WixGear 调用以 `ModelGatewayError` 失败。因此业务 Enrichment 与真实 E2E 属于延期的外部模型工作，**不是已验收交付物**。

## 2. 运行时链路

运行时业务数据从 Review Search 与 Claim Store 流入 ReviewSignal 聚合层。调查策略的固定顺序为：

```text
异常检测 → ReviewSignal → 检索（Keyword 默认，Qdrant 实验）
        → Review Detail → Evidence Guard
```

Golden 标签仅用于离线，运行时 repository 不读取。

### 向量后端

Qdrant 使用版本化的本地 `text-embedding-qwen3-embedding-0.6b` provider（1024 维）与 SHA-256 派生的稳定 Review ID。适配器与 300 条评论的冒烟路径已验证，但受控语料**不构成语义质量结论**。Qdrant 保持实验性；Keyword 是生产默认，因为当前 90 查询对比未能显示收益。

### Enrichment 运行器

Enrichment 运行器使用有界在途队列与网关熔断器。重复的 `ModelGatewayError` / 认证 / 配额失败会在少量阈值后停止新提交，保留未开始的行以便续跑，并发出 `blocked_model_gateway_error`，而不是烧掉剩余样本或把失败的预测标记为有效 Claim。

业务 Enrichment 与真实 Planner E2E 需要已充值的 DeepSeek 运行时；凭据不可用时保持显式阻塞。

## 3. 确定性本地模式

外部模型凭据不可用时，设置 `EXECUTION_MODE=deterministic_local`（无 DeepSeek Key 时也会自动选中）。API 随后在不发起网络模型调用的情况下运行本地 Core MVP 链路：

```text
Anomaly → ReviewSignal → Keyword Retrieval → Review Detail → Evidence Guard
        → 保守结论或弃权
```

该模式适用于本地开发、UI 评审、API/SSE 回归与操作演示。其结果会显式标记 `execution_mode=deterministic_local` 与 `planner_status=local_deterministic`，**不是**真实 Planner 或外部模型的验收结果。

使用 `EXECUTION_MODE=external_planner` 可强制要求外部 Planner。若其凭据缺失，调查以 `planner_unavailable` / `deferred_external_model` 结束，**不得伪造诊断**。

本地模式永不读取 Golden 标签、case ID 或历史评测结果。Evidence Guard 只接收本地 Review 工具实际观测到的 Review ID 与引文。

## 4. 本地发布手册

### 启动与检查

```bash
make install
make preflight
make verify
make backend
```

无外部模型时使用 `EXECUTION_MODE=deterministic_local`。健康检查 `/api/v1/health` 必须显示 `planner_status: local_deterministic`；外部模型状态只能标记为 deferred，**不得用旧结果代替**。

### 数据保护

```bash
make db-backup-all BACKUP_DIR=artifacts-backup
make db-restore-all BACKUP_DIR=artifacts-backup
```

统一命令使用 SQLite Online Backup API 保存 Investigation DB 与 Claim Store。备份前停止批量写入，恢复前保留当前数据库副本。

### 容器启动

```bash
docker compose up --build
```

浏览器访问 `http://127.0.0.1:5173`，前端经 Nginx 将 `/api` 转发到本地确定性 API。

### 发布边界

Keyword 是默认检索；char-bigram 与 Qdrant 为实验后端。业务 Enrichment、DeepSeek Planner 和真实语义 E2E 在模型网关恢复前保持 deferred。

## 5. 检索评测结论

冻结的 90 查询集已针对 Keyword、char-bigram Hybrid、Qdrant Vector 与 Qdrant+RRF 完成评测，结果归档于 `backend/artifacts/semantic_eval/retrieval_eval_qdrant_report_v1.json`。

受控的 300 条评论 Qdrant 语料**适用于基础设施验证，不构成语义质量结论**：许多冻结查询的相关 ID 不在受控语料内。因此 Keyword 保持默认，char-bigram Hybrid 保持实验性回退，Qdrant 在更大的业务语料到位前保持实验性。

## 6. 已知 Bad Case

当前主要 bad case 是**评测语料覆盖度**：当相关 Review 未被嵌入受控冒烟语料时，向量召回率被低估。这被记录为评测局限，**不静默转化为模型质量结论**。

## 8. 已知数据状态限制

### Claim Store 为空，评论信号对比面板无数据

`backend/artifacts/claim_store.sqlite3` 当前为**空库**（`claims: 0`、`manifests: 0`）。因此：

- `/api/v1/reviews/signals/compare` 对**任何周期**都返回 `insufficient_data: true` 与 0 个主题。
- 前端「主题与极性」对比区块固定显示「样本不足」，与所选周期无关。

**根因**：语义抽取（Review Semantic Enrichment）从未在业务全量上运行。按第 1 节所述，业务 Enrichment 与真实语义 E2E 因模型网关不可用而保持 deferred，Claim Store 未被填充。

**排查时注意**：该现象**不是**周期或时间窗口逻辑的问题——原先硬编码周期时同样是空的。要验证周期推导是否生效，应直接检查接口返回的 `current_period` / `baseline_period` 字段，而不是看面板是否有内容。

**恢复方式**：模型网关可用后运行离线 Enrichment 任务写入 Claim Store，本面板即恢复。在此之前，任何依赖该库的界面能力都不应被当作已验收。
