## S2 导入与追溯

已实现九个来源域：销售与流量、订单与发货、退款交易、退货状态、评论、售后工单、库存与可售、页面星级、价格促销与运营事件。字段映射和来源粒度有版本；数据先进入暂存区，再经核对发布。原文件按内容指纹保存，修订保留旧事实与原始行。空值不自动变零；ASIN 数据不复制到每个 SKU。

验收步骤：数据源 → 登记来源 → 下载列模板或映射原表列 → 声明报表对象、日期、生成时间和完整性 → 上传 CSV → 核对错误行 → 首次确认契约 → 发布。存在错误行时必须明确同意部分发布。发布后查看版本、完整性、原始行及原文件下载。重复上传同一份内容和声明不产生重复事实。

订单来源另需明确覆盖下单日期还是发货日期；退货来源明确统计申请或仓库收到。未知已购／Vine 标记保留未知，时间戳可保留时区。来源只提供日期时，成熟队列使用站点当日零点并显示精度约定。

目录接入通过服务端登记授权根目录，浏览器不能提交任意服务器路径。每份 `report.csv` 配套 `report.csv.json` 声明覆盖范围、生成时间、完整性及 ASIN 清单。两次稳定观察后才读取；读取中变更会回滚导入。首次来源契约仍需人工确认；自动发布只适用于已确认契约且无错误行的报表。缺文件或路径问题可在数据源查看。

剩余：真实脱敏报表兼容验证、全部来源字段与实际样本逐项核对、撤销发布及大文件／异常恢复验收。当前未将这些标为通过。

## 本地复现

环境文件 `.env.local` 已在本机配置，不能将真实密钥写入示例。启动数据库与 Redis：

```sh
docker compose --env-file .env.local -f compose.dev.yml up -d
```

在 `backend` 中安装依赖、迁移并准备测试账号；仅首次需要种子账号命令：

```sh
uv sync
uv run --env-file ../.env.local python manage.py migrate
uv run --env-file ../.env.local python manage.py seed_acceptance
uv run --env-file ../.env.local python manage.py seed_metric_acceptance
```

在三个独立终端运行 API、worker 和调度器：

```sh
uv run --env-file ../.env.local python manage.py runserver 127.0.0.1:8280 --noreload
uv run --env-file ../.env.local celery -A config worker --pool=solo --concurrency=1 --loglevel=WARNING
uv run --env-file ../.env.local celery -A config beat --loglevel=WARNING --schedule ../.local/celerybeat-schedule
```

在 `frontend` 中运行 `pnpm install`、`pnpm dev`。Node 使用已验证的 24 系列。当前 API 为本地开发服务，不能直接当作生产启动方案。后端使用 `--noreload`，修改代码后需要重启 API 与 worker。

验证命令：后端 `uv run --env-file ../.env.local pytest -c pytest-v2.ini`；前端 `pnpm build`、`pnpm exec playwright test`。浏览器测试要求上述服务正在运行，且已创建隔离的验收账号和指标样本。
