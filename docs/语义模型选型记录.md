# Review Semantic Layer 模型选型记录

## 1 实验目标

本轮实验用于判断 Stage 5.5A 的主要性能瓶颈来自 Prompt 还是模型能力，并为后续离线 Review Semantic Enrichment 选择工程候选模型。实验不用于证明模型已经通过全部语义验收，也不进入 Review Signal 月度聚合。

## 2 固定条件

- Golden 数据：360 Review、657 Claim，保持冻结。
- 本轮数据：Dev Split 216 Review；未运行 Validation 和 Frozen Test。
- Taxonomy：`taxonomy-v1.1`，保持冻结。
- Schema、Semantic Guard 和 Evaluator：各轮保持一致。
- 模型对照条件：DeepSeek 与 Qwen v1.0 均使用 `semantic-prompt-v1.0`。
- 业务全量：未运行 81,277 条业务 Review。

## 3 实验结果

| 指标 | Qwen v1.0 | Qwen v1.1 | Qwen v1.2 | DeepSeek v1.0 | 验收门槛 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Primary Topic Macro-F1 | 0.5691 | 0.6003 | 0.3885 | 0.7863 | 0.85 |
| Secondary Topic Micro-F1 | 0.5064 | 0.5322 | 0.3320 | 0.6971 | 0.75 |
| Topic × Polarity Micro-F1 | 0.5000 | 0.5243 | 0.3287 | 0.6782 | 0.70 |
| Matched-topic Polarity Accuracy | 0.9873 | 0.9789 | 0.9878 | 0.9631 | 0.85 |
| Evidence Substring Validity | 0.9567 | 0.9212 | 0.9444 | 1.0000 | 1.00 |
| Invalid Taxonomy Rate | 0.0512 | 0.0489 | 0.0159 | 0.0000 | 0.00 |
| Unsupported Evidence Rate | 0.0433 | 0.0788 | 0.0556 | 0.0000 | 0.00 |

DeepSeek 在同 Prompt 对照中显著提高了主题识别和 Topic × Polarity F1，并使 Taxonomy、Evidence 与 Unsupported Evidence 三项硬约束全部通过。216 条 Dev Review 共生成 496 条 Claim，处理错误为 0。

## 4 错误口径与已知限制

DeepSeek 仍有 80 条 Review 出现 Missing Topic、127 条出现 Extra Topic，145 条属于 Bad Case。报告中的 115 条 `polarity_mismatch` 是 Review 级复合标记，包含 Topic 缺失和额外 Topic 的影响；Topic 已匹配后的实际极性错误为 11 个 Claim，Matched-topic Polarity Accuracy 为 0.9631。

当前主要限制是 Topic 精度、Claim 边界和过抽取，而不是 Schema 合法性、Evidence 连续子串或单独的 Polarity 分类能力。单条 Claim 只能作为评论信号，不能直接视为经营异常的确定性原因。

## 5 最终选择

| 组件 | 决策 |
| --- | --- |
| 主语义模型候选 | DeepSeek v4 flash |
| Prompt | `semantic-prompt-v1.0`，冻结 |
| 本地开发与降级模型 | Qwen 3.5 9B，使用 `semantic-prompt-v1.0` |
| Taxonomy | `taxonomy-v1.1`，冻结 |
| Golden 与 Evaluator | 冻结 |
| Qwen v1.1 和 v1.2 | 仅保留为实验记录 |
| OpenAI | 有独立 Key 后再做对照，不阻塞工程主线 |

本项目暂将 DeepSeek 作为主要语义分析候选模型，Qwen 作为本地开发及降级模型。DeepSeek 不是 OpenAI `gpt-5.6-sol` baseline，也尚未通过全部语义评测门槛。

## 6 为什么停止 Prompt 调优

Qwen 的 v1.0、v1.1、v1.2 已显示召回、精度和 Guard 之间明显摆动；DeepSeek 在不修改 Prompt 的情况下取得更大提升，说明模型能力对当前结果影响更大。继续进行小幅 Prompt 试错容易形成 Dev 过拟合，也不能稳定解决 Golden 标注边界与模型过抽取之间的差异。因此不再创建 v1.3、v1.4，也不为追求指标修改 Taxonomy 或 Golden。

## 7 工程使用边界

语义抽取是离线或增量数据任务：原始 Review 经过版本化抽取、Schema 校验和 Semantic Guard 后写入 Claim Store，再由后续聚合层生成 Topic × Polarity × Time 信号。运行时 Agent 只查询指标、聚合信号和可回查 Evidence，不应在每次调查中实时分析数百条评论。

诊断层必须区分经营事实、评论信号和诊断推断。评论信号与经营指标方向一致时只能形成支持性证据，不能直接宣称因果；证据不足或存在冲突时必须保留未解释维度并停止归因。

Validation 与 Frozen Test 延后到 Release Candidate 阶段一次性执行，用于最终验收和记录，不再作为无限 Prompt 迭代的入口。
