## 5 迁移与需要用户参与的节点

主体选型确认后，先备份并建立新架构启动入口；旧实现短期保留用于回归对照。新增正式运行入口只连接新事实库，不把旧 SQLite 结果偷偷回退到新页面。纯函数经新用例验证后移植；旧自建 Agent 执行器不进入新业务路径。兼容旧接口只在明确必要且有移除计划时增加，避免长期维护两套语义。

用户必需决策：主体框架迁移方向（已确认）；模型服务商、传输区域及成本额度（S4 真实模型调用前）；真实来源权限、报表样本中无法判断的业务字段（遇到时）；生产服务器、域名、备份位置及凭据（S7 部署前）。不会要求用户逐一决定普通补丁版本、索引或内部函数设计；这些由实施兼容验证决定并记入锁文件。

可在缺真实数据时继续完成契约和合成案例开发；必须将来源标为合成，实际报表兼容和真实效果验收保留未通过状态。可在缺模型时使用明确标识的测试适配器验证工具流程，但不能将其作为自主调查模型验收。禁止把这两种缺口改写成“后续版本再做”。
