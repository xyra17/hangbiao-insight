## 失败原因、免费修复及证据界限

1. **词面未命中无法进入判定。** 已授权小范围即使只有一条“carton arrived crushed”，原规则仍会排除候选。现在在范围数量不超过既定候选上限时判断完整范围；超过上限保持有界词法候选，不扩大费用。补 `lexical_matched_count` 并区分候选策略。这个改动不代表大范围 Recall 已达标。
2. **后续提示词超过已批准的请求字节上限。** 原工具审计回执、费用和算法元数据占据提示词；同一范围被 reviews/support/反证重复描述。现在保留原文、引用、冻结对象/日期、限制、每次搜索状态和完整性，将相同范围及限制共享表示；持久轨迹保留完整原始结果，不删样本。不同范围不会合并。使用紧凑 JSON，仍检查实际 SDK envelope 和费用。
3. **planner HTTP 400。** 已确认所有 4 次被拒绝；原执行器仅保留异常类型，未保留供应商错误 body，所以不能断言供应商返回的具体原因。免费检查找到 TEXT_SCHEMA 的 source_field 在 strict schema 中仍为可选，现修正 wire required 并递归检查所有对象。此缺陷是可复现的本地发现，是否就是供应商拒绝原因仍需新真实验证。
4. **正例被 relevant + object unknown 拒绝。** 原文未重复 ASIN，但服务端已按对象冻结范围筛选。增加提示说明对象归属来自冻结 scope；范围缺失、查询不一致或原文明示冲突继续 unknown/conflicts。不把已有 unknown 结果改成通过。
5. **拒绝异常让调查停在 running 并允许 Job 再试。** 新 dispatch 将供应商错误转为终态 StructuredResponseError，保留 HTTP status、request ID、error body 及未知费用；调查转 partial，预算不退款。受影响行为已有真实数据库集成断言。

正例真实响应的 quote 连续原文存在，但 object unknown 仍阻断；否定原文和无关配送原文均返回 irrelevant。这些仅是 development 观察，未有独立人工裁决，不能扩成准确率或 24 对验收。
