# RAG 检索实现与验收

更新：2026-09-23。本文记录实际实现及未通过门槛，不替代总体技术方案。

## 证据链

结构化指标由 Python 领域服务计算并冻结为快照，不参与文本相似度计算。评论及售后文本按授权商品、业务日期、来源修订版本取最新有效事实；撤销评论不进入检索。原文和原始行不重写，检索索引是可重建派生数据。

新评论／售后事实发布时，在同一发布事务中生成中文分词字段、英文词干向量及 PostgreSQL GIN 索引。分词使用固定 jieba 0.42.1，内置词典版本为 `jieba-0.42.1-feedback-v1`。历史数据可运行 `python manage.py rebuild_evidence_index` 重建；升级分词或词典必须重建索引并重新评测。当前命令完整重建，超大规模在线重建及性能尚未验收。

查询结合原文短语、中文分词、英文词干及明确别名。英文短语按词边界处理，不能把 photos 误识别成 hot。排序使用 PostgreSQL 排名、日期与稳定事实 ID，不将其称为 BM25；当前未启用向量数据库、embedding 或模型重排。每次检索返回并审计范围、来源版本、分词及别名版本、命中事实 ID、原文和原始行引用。

## 当前入口

`POST /api/v1/evidence-search/`：要求店铺、子 ASIN、开始／结束日期和查询词；可限定 SKU 商品对象、评论或售后、最多 50 条返回。授权在取数前校验，ASIN 汇总要求该 ASIN 全部商品权限。页面入口为“调查报告 → 查询评论与售后原文”。当前页面使用 ASIN 汇总查询，SKU 专用查询界面仍待完善。

固定调查图已接入两类原文取证：启动时保存来源清单及最近 90 天日期范围，恢复沿用该范围。检索结果仅为探索证据，不计算总体主题率，也不证明退货与评论来自同一订单。指标与语义标签的全链路版本一致性、用户指定调查窗口、主题及极性过滤、完整反证流程仍待完成。

## 验证与发布门槛

固定合成回归集位于 `backend/tests_v2/fixtures/retrieval_cases.json`，包含 15 条文档、7 个中英文查询，覆盖分词、别名、词干、干扰文本和词边界。它用于验证机制，不能替代独立真实语料 Recall@10、低频问题覆盖及人工相关性标注。别名迭代发生在该开发集上，不能将该集同时称为未见过的测试集。

真实业务验收须另冻结脱敏语料、相关文档标注、查询与期望范围，分别测 Recall@10、误召回、时延和数据缺口；不达标时先检查范围与索引，再依据总体方案评估 pgvector 混合检索，不提前认定向量是必要组件。任何外部 embedding 或模型服务调用前须确认供应商、传输区域及预算。

当前未完成模型证据驱动的 Agent、业务反证与完整报告支持关系校验。不得把固定图、检索接口或流畅模型回答当作完整自主调查已验收。
