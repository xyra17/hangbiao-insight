## 1. 产品目标

航标 Insight 是面向跨境电商运营人员的商品经营异常诊断工作台。前端的核心任务不是“展示一堆图表”，而是帮助运营人员完成一条可验证的决策链：

```text
选择商品 → 发现经营异常 → 查看指标变化 → 发起 AI 调查
        → 跟踪调查轨迹 → 回查评论原文 → 明确结论与证据边界
```

### 目标用户

- 跨境电商运营分析师
- 商品负责人 / 类目负责人
- 需要复核经营异常的管理者

### 核心设计原则

1. **事实优先**：指标、时间范围、数据版本必须清晰，不以装饰性图表替代信息。
2. **证据可回查**：任何评论结论都应能回到 Review ID 和原始评论。
3. **不确定性可见**：样本不足、数据未接入、模型不可用、停止归因都必须明确展示。
4. **操作闭环**：异常必须能进入调查，调查必须能导出、追问和查看证据。
5. **运行模式透明**：`deterministic_local` 不能包装成真实外部模型能力。

## 4. 页面规格

### 4.1 全局框架

#### 左侧栏

- 品牌：航标 Insight / 跨境商品经营洞察
- 工作区切换器：首版仅展示，不提供虚假切换
- 主导航：显示图标、名称、说明；异常中心显示高风险数量徽标
- P1 导航项：置灰并显示 `P1`
- 底部：帮助与口径、数据源设置、用户信息
- 当前页面必须有明确的选中状态

#### 顶部栏

- 面包屑式上下文：`Amazon 美国站 · 运营诊断`
- 当前页面名称
- 全局搜索和通知：P1，禁用并提供 Tooltip
- 数据源状态：不能固定写死，应由 `/api/v1/health` 的 `data_sources.status` 驱动

#### 全局反馈

- API 错误使用页面顶部错误条；展示可理解的错误原因，不只展示 HTTP 状态码。
- 成功操作使用 Toast，例如“已导入 128 条记录”。
- 持续任务显示进度或运行状态，不允许点击后无反馈。
- 页面切换动画控制在 200–300ms；遵守 `prefers-reduced-motion`。

### 4.2 经营总览

#### 页面头部

- 标题：先看事实，再决定查什么。
- 当前日期、当前商品名称
- 商品选择器

#### KPI 区

四项指标：

1. 订单量
2. 退款率
3. 平均评分
4. 评论量

每张卡展示当前值、单位、相对上月变化、方向和语义色。注意：退款率上升通常是负向，不能仅按“上升=绿色”处理，应按指标业务含义映射颜色。

#### 经营趋势

- 同图展示订单量与退款率，双 Y 轴。
- X 轴为月份。
- 标记已知异常窗口。
- 显示数据版本 `source_version`。
- 窗口切换（6/12/18 月）驱动 `/api/v1/metrics/trend?months=`。**注意**：若要升级为 7/28 天滚动窗口，需先接入日粒度经营数据并扩展后端 `window` 参数——属数据前置项（V2 第 8.3 节），当前不可实现；在此之前不要保留可点击假按钮。

#### 异常雷达

- 默认展示前 4 条，按严重度和处理状态排序。
- 每条展示摘要、月份、信号数量、风险等级。
- 点击进入对应异常的 AI 深度诊断。
- “查看全部”跳转异常中心。

#### 评论信号结构

- Topic × Polarity 图表。
- 标明信号来自业务 Prediction Claim，不是 Ground Truth。
- 展示当前周期、基线周期、主题数量或样本不足状态。

> ⚠️ **已知数据状态限制**：本区块依赖 `claim_store.sqlite3` 的 Claim 数据。当前该库为**空**（`claims: 0`），因此 `/api/v1/reviews/signals/compare` 对**所有周期**都返回 `insufficient_data: true`，界面固定显示「样本不足」。
> 这与周期推导无关——原先硬编码 `2020-06` 时同样是空的；根因是语义抽取从未运行（见 [运行时状态与本地发布](运行时状态与本地发布.md) 第 8 节）。
> **验证周期切换是否生效时，不要以该面板是否有数据为准**，应直接查接口返回的 `current_period` / `baseline_period` 字段。

#### AI 调查引导卡

- 说明 Agent 的工作方式与证据边界。
- 快捷问题点击后应作为本次调查问题发起诊断。
- 主按钮：开始深度诊断。
- 数据未接入项以“待接证据源”展示，不生成占位数值。

### 4.3 商品中心

- 搜索条件：商品名称或 ASIN；支持清空搜索。
- 商品卡字段：站点、健康状态、ASIN、名称、类目、来源、评分、评论量、异常数。
- 点击商品卡：设置全局当前商品并进入经营总览。
- 当前商品卡有选中态。
- 无匹配商品时显示空态和清空搜索入口。
- “添加商品”本期禁用，Tooltip：需要接入商品主数据源。

### 4.4 异常中心

- 风险筛选：全部、高风险、中风险；若后端出现低风险，应补充低风险选项。
- 表格列：异常与商品、信号变化、时间、风险、诊断状态、进入按钮。
- 点击行进入诊断。
- 导出当前筛选结果为 CSV；中文需使用 UTF-8 BOM，避免 Excel 打开乱码。
- 空列表展示“当前筛选条件下没有异常”，并允许重置筛选。
- 表格在窄屏下改为卡片列表，避免横向压缩至不可读。

### 4.5 AI 深度诊断

#### 发起调查

请求：`POST /api/v1/investigations`

```json
{
  "user_query": "为什么退款率上升？",
  "product_id": "B07P9S6R9Y",
  "period": "2020-06",
  "max_steps": 8,
  "parent_investigation_id": null
}
```

前端必须处理多种路由响应，不能默认响应一定包含 `investigation_id`：

- `investigation_id`：创建成功，连接 SSE。
- `route=clarification`：展示缺失字段，引导用户补充。
- `route=unsupported`：展示暂不支持的原因。
- `route=tool/workflow`：直接展示同步完成的 `result`，不连接 SSE。

#### 调查状态

支持状态：

| 状态 | 展示语义 | 允许操作 |
| --- | --- | --- |
| `pending` | 等待执行 | 查看、离开页面 |
| `running` | 正在调查 | 实时查看轨迹 |
| `completed` | 调查完成 | 查看证据、导出、追问 |
| `stopped` | 已主动停止 | 查看停止原因、补充数据 |
| `failed` | 调查失败 | 查看原因、重试 |
| `timeout` | 调查超时 | 重试或缩小问题范围 |
| `planner_unavailable` | 规划模型不可用 | 查看本地能力说明 |
| `cancelled` | 已取消 | 重新发起 |

#### SSE 行为

- 创建成功后连接 `/api/v1/investigations/{id}/stream`。
- 收到事件后更新调查状态；推荐直接消费事件并局部更新，也可节流后 GET 最新状态。
- 保存最后的 SSE `id`，断线重连时传 `after_sequence`，避免重复事件。
- 终态后关闭连接。
- 组件卸载、切换调查或切换商品时关闭旧连接。
- 展示“正在重连”“连接已中断”等状态，不能静默失败。

#### 页面内容

- 页面头：运行模式、商品、周期、状态、父调查 ID。
- 调查轨迹：事件类型、步骤序号、动作摘要、时间；不要直接把 JSON 作为正式 UI。
- 最终诊断：结论、摘要、置信度、停止原因。
- 证据区：只展示通过 Evidence Guard 的证据；支持打开评论详情。
- 工具观察：显示工具名、结果摘要、状态；敏感或冗长原始数据折叠展示。
- 待补充信号：说明评论只能提供相关信号，提示退款原因、售后、库存等缺口。
- 操作：导出 Markdown、继续追问、创建后续分析。

#### 本地模式提示

当 `execution_mode=deterministic_local` 时持续展示但不干扰主任务：

> 本地确定性模式。外部规划模型未接入，当前结果用于本地回归，不代表真实模型验收。

### 4.6 评论洞察

#### 搜索

- 输入问题、体验或评论原文关键词。
- Enter 和按钮均可触发搜索。
- 搜索中禁用重复提交并显示加载状态。
- 搜索失败保留输入内容和上一批结果。

#### 主题与极性

- Topic × Polarity 图表。
- 基线/当前周期对比表：主题、极性、基线占比、当前占比、百分点变化。
- 样本不足时不绘制误导性百分比，显示原因。

#### 证据健康度

- Review ID 完整性
- 当前检索后端
- 检索版本
- Embedding 版本
- Qdrant 状态
- Topic 聚合信号状态

这里是“数据能力说明”，不是一个虚构的 100 分健康评分。现有环形图建议改为状态清单，避免造成精确度错觉。

#### 代表性评论

- 极性筛选：全部、正向、负向。
- 当前逻辑可暂以评分 `>=4` 为正向、`<=2` 为负向，3 星视为中性；最终应以后端 polarity 字段为准。
- 卡片展示评分、日期、标题、摘要、Review ID。
- 点击打开评论详情抽屉。

#### 评论详情抽屉

- 打开后调用 `/api/v1/reviews/{review_id}` 回查原文。
- 展示评分、日期、来源、标题、全文、完整 Review ID、Guard 状态。
- 支持遮罩点击、关闭按钮和 `Esc` 关闭。
- 打开后锁定背景滚动；关闭后焦点返回触发卡片。
- “加入当前调查”只有在存在活动调查时可用；否则禁用并说明原因。本期若不实现关联能力，应移除按钮，不能保留无行为按钮。

### 4.7 数据源管理

#### CSV 上传

支持 4 种类型：

| 类型 | 必填字段 |
| --- | --- |
| 经营指标 `business_metrics` | `product_id, period, orders, refund_rate` |
| 退款原因 `refund_reasons` | `product_id, period, refund_reason, count` |
| 售后记录 `after_sales` | `product_id, period, after_sales_code, count` |
| 库存 `inventory` | `product_id, period, stock, out_of_stock_days` |

交互要求：

- 仅接受 `.csv`；选择后展示文件名、大小和可移除操作。
- 上传中显示进度/忙碌态，禁止重复上传。
- 成功展示接受行数、错误行数和状态。
- `ready_with_errors` 必须展示质量报告，并允许查看前 20 条错误。
- `failed` 必须展示失败原因和正确字段模板。
- 重复文件由后端 hash 幂等处理，前端提示“已更新同一数据源”。

#### SQLite 探测

- 输入绝对路径并测试连接。
- 成功后展示表名和字段列表，而不只是“发现 N 张表”。
- 说明该操作只读、不上传、不覆盖现有经营指标。

#### 已配置来源

- 字段：名称、类型、Source ID、记录数、状态、更新时间、质量结果。
- 空态：暂无业务数据源，系统继续使用安全的本地演示模式。

## 6. 前端状态模型

每个数据模块至少覆盖以下状态：

| 状态 | UI 处理 |
| --- | --- |
| 初始加载 | 骨架屏；不要整页无限旋转 |
| 局部刷新 | 保留旧数据，局部显示刷新状态 |
| 成功有数据 | 正常展示 |
| 成功无数据 | 有下一步指引的空态 |
| 样本不足 | 明确说明，不展示误导性图形 |
| 请求失败 | 展示原因、重试入口，保留用户输入 |
| 未配置 | 解释缺少的数据源和配置入口 |
| 禁用 | 显示原因，不只降低透明度 |

建议使用 TanStack Query 管理服务端状态；页面筛选、抽屉、当前商品等轻量 UI 状态可使用 React Context 或 Zustand。若不引入状态库，也必须将请求逻辑从页面组件中抽到 hooks。

## 7. API 对接清单

基础地址由 `VITE_API_BASE` 配置；本地 Vite 通过 `/api` 代理到 `http://127.0.0.1:8200`。

| 页面 | 方法 | 接口 | 用途 |
| --- | --- | --- | --- |
| 全局 | GET | `/api/v1/health` | 运行模式、Planner、检索和数据源状态 |
| 总览 | GET | `/api/v1/overview?product_id=` | 商品、KPI、趋势、异常、覆盖情况 |
| 商品 | GET | `/api/v1/products` | 商品列表 |
| 趋势 | GET | `/api/v1/metrics/trend?product_id=&months=` | 指标趋势 |
| 异常 | GET | `/api/v1/anomalies?product_id=` | 异常列表 |
| 异常 | GET | `/api/v1/anomalies/{id}` | 异常详情 |
| 评论 | GET | `/api/v1/reviews/topics?product_id=&period=` | Topic 聚合 |
| 评论 | GET | `/api/v1/reviews/signals/compare?...` | 基线与当前信号对比 |
| 评论 | GET | `/api/v1/reviews/search?product_id=&q=&limit=` | 关键词检索 |
| 评论 | GET | `/api/v1/reviews/{review_id}` | 评论原文回查 |
| 调查 | POST | `/api/v1/investigations` | 创建调查或路由任务 |
| 调查 | GET | `/api/v1/investigations/{id}` | 获取调查状态 |
| 调查 | GET/SSE | `/api/v1/investigations/{id}/stream` | 实时事件 |
| 数据源 | GET | `/api/v1/data-sources` | 已配置来源 |
| 数据源 | POST | `/api/v1/data-sources/upload?kind=` | 上传 CSV |
| 数据源 | GET | `/api/v1/data-sources/sqlite/inspect?path=` | 只读探测 SQLite |

### API Client 统一要求

- 统一解析 FastAPI 错误体 `{ "detail": "..." }`。
- 区分 400、404、422、500 和网络错误，生成用户可理解的提示。
- 支持 AbortController，切换商品或离开页面时取消旧请求。
- 只对幂等 GET 做有限重试；POST 调查和文件上传不可自动重复提交。
- 接口类型集中维护，不使用 `any` 表示调查状态。
- 所有日期与百分比使用统一 formatter。

## 8. 视觉规范

### 视觉方向

整体采用“运营控制台”语言：深海军蓝导航、白色工作画布、紫色作为交互主色；绿色表示已验证或健康，琥珀表示待确认，红色表示风险。视觉重点放在异常与证据链，不使用无业务含义的渐变和装饰卡片。

### 建议统一的基础 Token

现有 `styles.css` 中存在多组重复 `:root` 和多轮覆盖。工程化时请收敛为单一 Token 源：

```css
:root {
  --color-bg: #f4f6fa;
  --color-surface: #ffffff;
  --color-sidebar: #182338;
  --color-text: #1d2942;
  --color-text-secondary: #5f6b80;
  --color-text-muted: #7f899b;
  --color-border: #dfe4ed;
  --color-primary: #5d50c8;
  --color-primary-soft: #f0eeff;
  --color-success: #238e7b;
  --color-warning: #b97922;
  --color-danger: #c95462;
  --radius-sm: 8px;
  --radius-md: 12px;
  --radius-lg: 16px;
  --shadow-panel: 0 8px 24px rgba(30, 43, 71, 0.06);
}
```

### 字体与密度

- 字体：`Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`
- 正文不得小于 14px；辅助文字不得小于 12px。
- 页面标题约 30–32px，模块标题 15–18px。
- 行高正文 1.5–1.7；评论正文 1.75 左右。
- 不使用全大写英文作为每个模块的装饰性眉题；仅在确有系统状态含义时使用。

### 响应式

- `>1280px`：三栏调查布局、四列 KPI、三列评论证据。
- `701–1280px`：保留完整侧栏或压缩至 220px；主内容改两栏/单栏。
- `<=700px`：侧栏应改为抽屉或底部导航；现有固定侧栏方案会占用移动端空间，需要重做。
- 表格在移动端转为卡片，不依赖横向滚动完成主要任务。
- 评论详情抽屉移动端占满宽度。

### 无障碍

- 所有图标按钮提供可访问名称。
- 键盘可完成导航、筛选、开关抽屉和发起诊断。
- 焦点态必须可见。
- 不能只靠颜色传达风险等级或涨跌。
- 图表提供文字摘要或数据表替代。
- Modal/Drawer 使用焦点圈定，关闭后恢复焦点。

## 9. 当前实现中必须修正的问题

以下问题来自现有原型，前端重构时不要原样继承：

1. `App.tsx` 集中了页面、请求、业务状态和组件，需拆分。
2. 调查创建逻辑默认响应必有 `investigation_id`，没有处理 router 的同步响应和澄清响应。
3. SSE 收到每个事件后立即整单 GET，缺少节流、断线恢复、终态关闭和组件卸载清理。
4. “查看全部”、商品搜索、快捷问题、“加入当前调查”等存在无行为或半行为控件。
5. 趋势 6/12/18 月按钮只有样式，没有真实筛选。
6. 数据源顶部状态固定为“数据已连接”，未读取健康接口。
7. 上传接口后端使用 query 参数 `kind`，现有 `apiUpload` 放在 FormData 字段中；联调前必须统一，否则可能返回 422。
8. 错误处理只显示“请求失败：状态码”，没有解析后端 `detail`。
9. 调查对象大量使用 `any`，容易遗漏状态和字段。
10. 调查轨迹直接 `JSON.stringify`，不适合作为正式产品界面。
11. 评论抽屉缺少 Esc、焦点管理、滚动锁定；“加入当前调查”没有实现。
12. 异常 CSV 未加 BOM，Windows Excel 可能出现中文乱码。
13. 多组 CSS Token 和样式覆盖导致维护困难，需要收敛。
14. 多处历史样式把辅助文字压到 8–10px，低于可读性下限。
15. 手机端仍保留固定侧栏，实际可用宽度不足。
16. CORS 白名单只包含 5173，而本地前端使用 5174；开发代理可绕过，但直连 API 或独立部署时需修正。

## 13. 交付定义

前端完成不以“页面长得像原型”为标准，而以下列结果为准：

- 用户能从异常发现走到证据回查，主链路不中断。
- 所有结论都能看见数据来源、时间范围和能力边界。
- 未接入能力不会伪装成已可用。
- 流式调查在成功、停止、失败、超时和断线情况下都有明确状态。
- 页面在常用桌面宽度和手机宽度下均可完成主要任务。
