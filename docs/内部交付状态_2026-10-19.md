## R1–R5 累积进展

R1–R5 的工程工作已覆盖以下护栏和恢复路径：

- **隔离启动与清理：** 开发及验收服务使用独立项目、端口、队列、存储和数据库；启动前确认资源归属，结束时只清理本轮自有进程。本轮 cleanup 收据确认自有临时服务残留为 0，未停止共享服务。
- **来源确认与版本冻结：** 经营事实读取需要已确认的授权来源。同一 run 续跑或中断恢复沿用原冻结输入；源版本修订时可创建新的只读 successor，并在创建时明确预选新 manifest/快照。successor 首次冻结后输入不漂移，旧 run 保持不变。
- **工作空间成本与并发：** 已实现工作空间日/月模型预算账本、跨调查共享累计、并发准入与槽位释放。额度和币种须由产品责任人配置，未配置或禁用策略时关闭外部模型路径（fail closed）。本轮免费验证关闭所有真实 provider，因此没有供应商费用；不在此文虚构额度。
- **进程中断与恢复：** 使用真实子进程执行项目 `run_job`，在调查节点已提交而 checkpoint 尚未提交的边界 kill 子进程，再恢复并验证节点不重复提交。运行中取消会停止后续节点写入并释放槽位；中断调查可恢复。覆盖执行租约回收、等待任务重新准入，以及新只读 successor 保留创建时预选的来源 manifest 和快照 ID；已取消的 run 不会被重新启动。

kill 测试针对项目任务子进程，不等同于完整 Celery broker 确认/重投递验证，也不覆盖整机断电或主机级故障恢复。当前证据可以支持应用任务层的中断恢复结论，不能外推为所有基础设施故障均已验收。
