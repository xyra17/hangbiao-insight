# 本地数据源导入

本文记录现有导入格式，不代表冻结需求已实现。目标数据契约以 [V2 第 8 节](阶段1_需求分析与MVP设计_V2.md) 为准；当前月度汇总格式不能代替日数据、订单关联和销售队列验收。

系统支持两种不依赖外部 API 的数据源方式：

## CSV 上传

通过前端“数据源”页面或 API 上传。支持类型及必需字段：

| 类型 | 字段 | 状态 |
| --- | --- | --- |
| `business_metrics` | `product_id, period, orders, refund_rate` | 已接入 |
| `refund_reasons` | `product_id, period, refund_reason, count` | 已接入 |
| `after_sales` | `product_id, period, after_sales_code, count` | 已接入 |
| `inventory` | `product_id, period, stock, out_of_stock_days` | 已接入 |
| `price_promo` | `product_id, period, price, promo_type` | **待实现（目标范围 FR-02）** |

`period` 必须为 `YYYY-MM`，`refund_rate` 必须在 0–1 之间。每次导入会生成输入 hash、错误行明细和质量报告，并按 hash 幂等写入 `backend/artifacts/data_sources.sqlite3`。

> `price_promo` 属于 V2 的统一交付范围。此表为原有设计字段；实际开发须按 V2 第 8 节补充对象维度、生效时间、币种和来源信息，不能只按月汇总字段完成验收。

## 本地 SQLite

`GET /api/v1/data-sources/sqlite/inspect?path=/absolute/path/file.sqlite3` 以只读方式探测数据库表和字段，不上传文件，也不会自动覆盖当前经营指标。确认映射后，再将数据导出为上述 CSV 格式导入，避免对未知业务表做隐式写入。

当前导入数据主要用于数据源登记、质量检查和后续 Provider 接入。

> **目标范围**：各数据源适配器、质量状态、证据消费与缺失处理必须按 V2 第 7 至 10 节统一实现并验收；不能将“已上传文件”等同于“可用于诊断”。未接入时不生成占位数值。
