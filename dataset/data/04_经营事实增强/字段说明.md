# 字段说明

本包字段按 [backend/insight/models.py](../../../backend/insight/models.py) 与 `backend/insight/ingestion/contracts.py` 的九域导入契约命名。原始增强 CSV 在契约字段外带来源/边界标记；`prepare_business_facts_import.py` 保留可追溯的 provenance 列为显式 `ignored_columns`，其它主题标签辅助列不进入导入 CSV。导入批次的 `StagedRow.raw` 会留存这些 provenance 标记。

## 九类事实契约

| 契约 | 本包文件 | Django 模型 | 粒度 |
|---|---|---|---|
| `sales_traffic` | `sales_traffic_daily_v1.csv` | `SalesTrafficDaily` | `asin_day` |
| `orders` | `orders_v1.csv` | `OrderLine` | `product_record` |
| `refunds` | `refunds_v1.csv` | `RefundTransaction` | `product_record` |
| `returns` | `returns_v1.csv` | `ReturnLifecycle` | `product_record` |
| `reviews` | 现有评论文件（本包不改写） | `Review` | `asin_record` |
| `support` | `support_cases_v1.csv` | `SupportCase` | `asin_record` |
| `inventory` | `inventory_daily_v1.csv` | `InventorySnapshot` | `asin_day` |
| `ratings` | `ratings_daily_v1.csv` | `RatingSnapshot` | `asin_day` |
| `operations` | `operations_v1.csv` | `OperationEvent` | `asin_record` |

## 事实字段

所有表共有 `child_asin` 和 `business_date`。商品日表允许 `seller_sku`、`fulfillment` 留空；订单、退款、退货用 `product_record`，因此需要 `<ASIN>-FBA` 和 `FBA` 商品映射。

| 文件 | 核心字段 | 字段含义与注意点 |
|---|---|---|
| `sales_traffic_daily_v1.csv` | `ordered_units`, `order_count`, `sessions`, `buybox_percent`, `sales_amount`, `currency` | 订单数来自既有合成经营指标；单位、sessions、Buy Box 和金额是确定种子下的合成/派生补齐。金额均为 USD。 |
| `ratings_daily_v1.csv` | `rating`, `rating_count` | 从真实评论记录按 ASIN/截至日期累计聚合，rating 为累计评论均值，rating_count 为累计评论数；不是页面星级的原始每日快照。 |
| `inventory_daily_v1.csv` | `available`, `reserved`, `inbound`, `unsellable`, `total`, `listing_status` | 由 synthetic 订单/单位计算出的库存演练值；0 可售与 suppressed 只用于边界测试。 |
| `operations_v1.csv` | `record_id`, `event_type`, `description`, `ends_on`, `price`, `currency`, `mechanism` | 记录基线价格、月优惠和合成情景运营事件；事件不是实际调价或促销。 |
| `orders_v1.csv` | `record_id`, `order_id`, `quantity`, `shipped_date`, `shipped_at`, `shipped_quantity`, `original_line_id`, `is_exchange`, `status` | 单行是合成订单行；status 涵盖 shipped/pending/cancelled/revised，部分样例用于修订或撤销演练。 |
| `refunds_v1.csv` | `record_id`, `order_line_id`, `transaction_chain_id`, `amount`, `currency`, `quantity`, `occurred_at` | 正数退款；负数代表同币种同 chain 冲正。`partial/full/reversal/late` 类型为源 CSV 辅助列，不导入模型。`ZZZ` 是三位大写但未知的币种代码，用于语法通过、币种未知的边界。 |
| `returns_v1.csv` | `record_id`, `order_line_id`, `quantity`, `reason`, `status`, `requested_date`, `received_date`, `requested_at`, `received_at` | 申请/收到日期可跨月；`source_pending_vendor_v2` 是故意的来源原始状态，当前契约会明确归一成 `unknown`。 |
| `support_cases_v1.csv` | `record_id`, `order_line_id`, `text`, `status` | `text` 明确以 `[SYNTHETIC SUPPORT CASE]` 开头；类别和黄金主题只用于数据生成及校验，不进入契约字段；来源评论关联保留在 `synthetic_from_review` 审计列。 |
| 现有 review 文件 | `record_id`, `title`, `text`, `rating`, `language`, `collected_at`, `is_deleted`, `verified_purchase`, `is_vine` | 本增强包不复制、不修改、不导入一份替代评论表。 |

## provenance 字段

主 CSV 的每行均带以下来源字段；布尔值写为小写 `true/false`。这些字段由转换器列入 SourceContract 的 ignored list，并由导入器留存在原始 StagedRow 中。

| 字段 | 说明 |
|---|---|
| `provenance_class` | `derived_from_synthetic_metrics`、`derived_from_real_reviews`、`synthetic` 或 `synthetic_from_golden_review_theme`。 |
| `is_real` | 该行是否直接复制真实经营事实。本包所有输出行均为 `false`；ratings 是真实评论聚合，所以 `is_derived=true`。 |
| `is_derived` | 是否经过确定性聚合/映射/计算。 |
| `is_synthetic` | 是否包含合成场景、模拟经营值或合成客服模板。派生自 synthetic 指标的值同时标为 derived 和 synthetic。 |
| `source_reference` / `source_row_id` | 输入文件与来源日/评论 claim 的可追溯标识。 |
| `generation_version` | 生成脚本版本；当前为 `business-facts-augmentation-v1.0`。 |
| `scenario_id` / `boundary_case` / `currency_case` | 合成情景、生命周期边界和币种边界说明。 |
| `synthetic_from_review` | 客服合成夹具对应的公开评论 `review_id`；绝不表示客服系统中的真实 case ID。 |

## 空值、零值与日期

- 日期字段采用 `YYYY-MM-DD`，时间戳为带 `Z` 偏移的 ISO 8601。
- 空值留空，不用 0 代替未知值。`available=0` 是明确构造的库存值；空 `received_date` 表示尚未收到或来源没有收到时间。
- 主日表是稀疏 ASIN 日期范围，转换 sidecar 默认 `declared_complete=false`。遗漏日期仍表示未知，不是 0。
- `returns` sidecar 以 `return_event=received` 配置覆盖口径；revision fixtures 的 requested 状态只提供申请日期，收到状态另发一个更高 revision。
- `refunds.amount` 可为负数；不同 currency / transaction chain 不得相互抵销。

## 边界文件

- `lifecycle_revisions/`：相同业务键分批上传，依次检验修订；包括申请→收到→来源更正为取消、订单更正、撤销候选和迟到 40 天的退款。
- `boundary_cases/`：非法 ASIN、同批重复键、币种格式错误、日期倒置及 header-only 空退款文件。每个都标出预期行为；它们不得并入正常文件。
- `expected_results.json`、`validation/validation_report.json`：固定行数、必需边界场景、覆盖、键、关联和来源标记校验。
